# PPT 슬라이드 생성 가이드라인 — 범용/기본값

이 문서는 신규 PPT(.pptx) 슬라이드를 생성할 때 항상 적용하는
**범용 디자인 톤앤매너 기본값**입니다. Claude는 별도 지시가 없는 한 아래 규칙을
기본값(default)으로 따릅니다. `[ ]` 표시된 항목은 회사/프로젝트 상황에
맞게 실제 값으로 채워 넣으세요.

> ⚠️ **우선순위 규칙**: 프로젝트 폴더에 `ppt_design_guideline.md`가 별도로
> 존재하면, 해당 문서가 이 문서보다 **우선 적용**된다. `ppt_design_guideline.md`가
> 명시하지 않은 항목(캔버스 규격, 여백, 도형 기본 스타일 등)에 한해 이 문서의
> 규칙을 기본값으로 따른다. 즉, 두 문서를 함께 참고하되 충돌 시
> 프로젝트별 가이드가 우선한다.

---

## 0. 작업 시작 워크플로우 — 레이아웃(슬라이드 마스터) 결정

PPT 작성 요청을 받으면 **본격적인 슬라이드 제작 전에** 아래 순서를 먼저 수행한다.
전반적인 레이아웃(슬라이드 마스터)을 먼저 확정하는 것이 개별 슬라이드 디자인보다 우선이다.

**STEP 1 — 참고 템플릿 제공 의향 확인 (필수)**
- 슬라이드를 만들기 전에 사용자에게 **참고할 프레젠테이션 템플릿을 제공할 의향이 있는지** 먼저 물어본다.
- 제공 가능한 형식을 함께 안내한다:
  - **URL** (예: 템플릿 배포/미리보기 페이지)
  - **.ppt / .pptx 파일** (기존 프레젠테이션 첨부)
  - **이미지** (슬라이드 캡처/시안 이미지)

**STEP 2-1 — 템플릿을 제공한 경우**
- 제공된 템플릿의 **레이아웃 구조와 톤앤매너를 분석**한다:
  - 슬라이드 마스터/레이아웃 종류(표지, 목차, 섹션 구분, 본문 1단·2단, 표/차트 전용, 마무리 등)
  - 제목·본문·footer 위치와 크기, 여백 그리드
  - 색상 팔레트, 폰트 종류·크기, 도형 스타일, 반복 모티프
- 분석 결과를 바탕으로 **그에 준하는 레이아웃(슬라이드 마스터)을 작성**하고, 내용을 **`ppt_design_guideline.md`에 반영**한다 (해당 파일이 없으면 새로 생성). 이후 슬라이드는 이 마스터에 준하여 일관되게 제작한다.
- .pptx 파일을 받은 경우, 실제 슬라이드 마스터/레이아웃을 재현·활용하도록 한다.

**STEP 2-2 — 템플릿을 제공하지 않은 경우**
- 기존에 정의된 톤앤매너(이 `ppt_designer.md`, 그리고 존재한다면 `ppt_design_guideline.md`)를 그대로 활용한다.

## 1. 색상 (Color Palette)

- **주조색(Primary, 60~70%)**: `[#0F2A4A]` — 제목, 배경, 주요 도형
- **보조색(Secondary, 20~30%)**: `[#5B7FA6]` — 강조 텍스트, 보조 도형
- **포인트색(Accent, 5~10%)**: `[#F2A93B]` — 그래프 강조, 숫자 콜아웃, CTA
- **배경 기본색**: 라이트 슬라이드 `#FFFFFF` / 다크 슬라이드 `[#0F2A4A]`
- **본문 텍스트**: `#333333` (라이트 배경) / `#F5F5F5` (다크 배경)

규칙:
- 색상은 항상 3색 이내(주조/보조/포인트)로 제한. 모든 색을 동일 비중으로 쓰지 않는다 — 반드시 하나의 색이 우세하도록 구성.
- 표지(Title) 슬라이드와 마무리(Closing) 슬라이드는 다크 배경, 본문 슬라이드는 라이트 배경으로 하는 "샌드위치 구조"를 기본으로 한다. (다크 톤 일관 유지도 가능하나 임의 혼용 금지)
- Hex 코드는 `#` 없이, 6자리로 지정 (예: `pptxgenjs` 사용 시 `"0F2A4A"`). 8자리(투명도 포함) 코드 사용 금지.
- 그래프/차트 색상도 위 팔레트에서만 선택(임의의 기본 팔레트 사용 금지).

## 2. 폰트 (Typography)

### 2-1. 폰트 종류
- **제목용 폰트**: `[Cambria]` (또는 `Bookman Old Style`, `Century Schoolbook`) — 세리프 계열로 신뢰감/격식 부여
- **본문/보조 텍스트 폰트**: `[Calibri]` (또는 `Arial`)
- 제목(세리프) + 본문(산세리프) 페어링을 기본으로 하여 시각적 대비를 준다.
- **사용 금지/주의 폰트**: `Aptos`(대체 폰트 호환성 문제로 사용 금지), 사용자가 명시적으로 요청하지 않는 한 `Georgia`, `Trebuchet MS`, `Impact` 등 비표준 폰트는 지양 (텍스트 박스 크기 여유를 10% 이상 확보해야 함)

### 2-2. 폰트 크기
| 요소 | 크기 | 스타일 |
|---|---|---|
| 슬라이드 제목 (Title) | 36–44pt | Bold |
| 섹션/소제목 (Section Header) | 20–24pt | Bold |
| 본문 텍스트 (Body) | 14–16pt | Regular |
| 캡션/출처/각주 (Caption) | 10–12pt | Regular, 회색 계열 |
| 강조 숫자/통계 (Stat callout) | 60–72pt | Bold |

### 2-3. 텍스트 규칙
- 자간 조정이 필요할 경우 `charSpacing` 속성 사용 (`letterSpacing`은 미반영되므로 사용 금지)
- 리스트는 항목마다 `bullet: true` 속성으로 처리하고, 텍스트에 `•` 문자를 직접 입력하지 않는다.
- 제목, 섹션 헤더, 인라인 라벨(예: "구분:", "담당:")은 Bold 처리.

## 3. 도형 (Shape) 사용 규칙

- **사각형 대신 둥근모서리사각형(Rounded Rectangle) 사용을 기본으로 한다.**
  - 카드형 콘텐츠 블록, 아이콘 배경, 버튼/CTA, 이미지 프레임 등 모든 사각형 요소에 적용
  - `rectRadius`(모서리 반경)는 도형 높이의 약 8~12% 수준으로 설정 (너무 둥글어 캡슐처럼 보이지 않도록 주의)
  - 순수 `RECTANGLE`은 원칙적으로 사용하지 않으며, 배경 전체를 덮는 컬러 블록/이미지 마스크 등 예외적인 경우에만 허용
- **아이콘**은 원형(Circle) 배경 안에 배치하는 것을 기본 스타일로 한다 (예: 포인트색 원 + 흰색 아이콘)
- **강조선/구분선**은 얇은 직선(hairline) 또는 도형의 accent 색상 테두리로 처리하며, 상단/좌측에 두꺼운 컬러 바(accent bar)를 반복 모티프로 사용하지 않는다.
- 하나의 시각적 모티프(예: 둥근모서리 이미지 프레임 + 원형 아이콘)를 정하면 전체 슬라이드에서 일관되게 반복 사용한다.
- 그림자(shadow) 사용 시 `offset`은 항상 0 이상 값 사용 (음수 불가, 위로 그림자를 주려면 `angle: 270` + 양수 offset 사용).

## 4. 레이아웃 & 여백

- 전체 슬라이드는 **하나의 슬라이드 마스터(공통 그리드)** 위에서 구성한다. 제목·footer·여백 기준을 슬라이드마다 임의로 바꾸지 않는다.
- 슬라이드 여백: 최소 0.5인치
- 콘텐츠 블록 간 간격: 0.3–0.5인치
- 슬라이드마다 반드시 하나 이상의 시각 요소(이미지, 차트, 아이콘, 도형) 포함 — 텍스트만으로 구성된 슬라이드 지양
- 레이아웃 패턴 예시 (콘텐츠 성격에 맞게 선택하되, 동일 유형 슬라이드는 같은 패턴 사용):
  - 2단 구성 (좌: 텍스트 / 우: 이미지·아이콘)
  - 아이콘 + 텍스트 로우 반복형
  - 2x2 또는 2x3 그리드
  - 하프블리드 이미지 + 텍스트 오버레이
  - 표/차트 전용 (제목 + 편집 가능한 표·차트 + 캡션)

## 5. 캔버스 규격

- 기본 와이드스크린: **13.3" × 7.5"** (`LAYOUT_WIDE`)로 설정 (기본값 10" × 5.625" 아님에 주의)
- 슬라이드 추가 전 반드시 레이아웃 크기를 먼저 지정

---

## 6. 차트 · 표 — 편집 가능한 형태로 작성 (중요)

- **차트와 표는 반드시 수정 가능한 네이티브 객체로 작성한다. 이미지로 삽입하지 않는다.**
  - 차트: PowerPoint 네이티브 차트 객체(`addChart`)로 생성하여 데이터·색상·라벨을 편집할 수 있게 한다. 차트를 캡처한 PNG/JPG를 붙여넣지 않는다.
  - 표: 네이티브 표 객체(`addTable`)로 생성하여 셀 내용을 편집할 수 있게 한다. 표를 이미지로 렌더링하지 않는다.
  - (단, 원본 자체가 편집 불가능한 스캔/이미지 자료인 경우는 예외이며, 이 경우 사용자에게 명시적으로 알린다.)
- **도식화 과정에서 값·표현 누락 여부를 더블체크한다.**
  - 원본 데이터/표/텍스트의 모든 값, 라벨, 항목, 각주, 단위 등이 슬라이드에 빠짐없이 반영되었는지 대조 확인한다.
  - **구현상의 어려움으로 부득이하게 누락한 경우, 반드시 사용자에게 보고하는 것을 원칙으로 한다.** (무엇을, 왜 누락했는지 명시하고 대안을 제시)
  - 누락 없이 완성했더라도, 값이 많거나 복잡한 경우 반영 여부를 간단히 요약해 사용자가 검증할 수 있게 한다.

## 7. 체크리스트 (슬라이드 완성 후 확인)

- [ ] (작업 시작 시) 참고 템플릿 제공 의향을 사용자에게 확인했는가
- [ ] 색상이 지정된 팔레트(주조/보조/포인트) 내에서만 사용되었는가
- [ ] 사각형 요소가 둥근모서리사각형으로 처리되었는가
- [ ] 제목/본문 폰트와 크기가 규정된 범위를 따르는가
- [ ] 슬라이드마다 시각 요소가 최소 1개 이상 포함되었는가
- [ ] 여백 및 간격 기준을 지켰는가
- [ ] 차트·표가 이미지가 아닌 편집 가능한 네이티브 객체로 작성되었는가
- [ ] 원본의 값·라벨·항목이 누락 없이 반영되었는가 (누락 시 사용자에게 보고했는가)
