# requirements-analysis

## 루프 계약
- 성공 기준: 모든 요구사항에 ID, 출처 위치(파일:쪽/줄), 검증 가능한 인수 조건, 우선순위가 있다. 모호한 점은 모두 사용자가 해소했거나 미결 질문으로 나열되어 있다. 출처 없는 요구사항은 없다.
- 검증자: 새 컨텍스트의 `evidence-verifier`가 명세를 원문과 대조해, 출처 없는 요구사항과 요구사항으로 옮겨지지 않은 원문 진술을 보고한다.
- 중단 조건: 검증자 FAIL이 2회 나오거나 미해결 모호성이 10개를 넘으면 멈추고 어느 것을 먼저 풀지 사용자에게 묻는다. 막히면 dispatch.md의 BLOCKED 규칙.

## 절차
1. 목표 한 줄과 범위(안/밖)를 정한다. 결과가 분명한 일에만 강제하고 창작·탐색은 선택이다. 프로젝트 수준이면 `.ai/INTENT.md`에 두되, 이미 있으면 변경은 제안만 하고 사람 승인 뒤에 기록한다.
2. 입력 문서와 분량을 나열한다. 큰 입력은 읽기를 `explorer`에게 맡기고 전문이 아니라 색인(절 -> 주제)을 받는다.
3. 요구사항을 다음 열로 추출한다: ID | 진술 | 유형(기능 / 비기능 / 제약) | 출처 | 인수 조건 | 우선순위.
4. 사실과 가정을 구분한다. 가정은 `ASSUMPTION`으로 표시하고 승인용으로 나열한다.
5. 모호성 목록을 만든다: 질문 | 막는 이유 | 선택지와 기본값. 해석이 여럿이면 하나를 몰래 고르지 않는다. 사용자에게는 한 번에 하나씩 묻고 문서가 답하는 것은 묻지 않는다.
6. 요구사항 사이의 의존 관계(A는 B가 필요)를 표시한다. 순서가 있는 작업을 여러 agent에 쪼개지 않는다.
7. 사용자 승인을 받는다. 승인된 명세는 dispatch.md의 승인 기록 규칙대로 해시를 남기고 바뀌면 재승인한다. 설계는 승인 후에 시작한다.

## 출력 템플릿
```
# 명세: <이름>  (출처: <파일>)
## 요구사항
| ID | 진술 | 유형 | 출처 | 인수 조건 | 우선순위 |
## 가정 (승인 필요)
## 미결 질문
| # | 질문 | 막는 것 | 선택지 (기본값 먼저) |
## 범위 밖
```
`.ai/INTENT.md` 형식(60줄 이하, 한 줄에 사실 하나): 목표 한 줄 / 범위 안·밖 / 제약 / 주요 결정(날짜 | 결정 | 이유 | 근거 링크) / 열린 질문 / 완료 확인.
INTENT 저장·분리(기본은 단일 파일): 자동 흐름은 루트 `.ai/INTENT.md`에만 쓴다. 세부 의도 파일(`.ai/intent/intent_<slug>.md`)은 `/intent` 명령의 규칙으로 만든다.

## 문체
중립적으로 쓰고 설득하는 표현을 쓰지 않는다. 숫자에는 단위를 붙인다. 법적·계약적 내용은 원문을 그대로 인용한다.
