# ui-ux-design

## 루프 계약
- 성공 기준: 화면마다 목적, 주된 행동, 모든 상태(빈 화면, 로딩, 오류, 성공, 권한 없음), 모든 라벨·메시지의 문구가 있다. 각 사용자 흐름이 정해진 단계 수 안에 목표에 도달한다. 접근성 기본 사항(대비, 키보드 경로, 터치 영역)을 확인했다.
- 검증자: 사용자가 화면마다 검토한다(반복적이고 취향으로 판단하는 작업이므로 agent가 아니라 메인 세션에서 한다). 선택적으로 아래 체크리스트로 `reviewer`가 마지막 점검을 한다.
- 중단 조건: 화면 하나에서 수정 3회 후에도 수렴하지 않으면 두 대안을 나란히 보여 주고 사용자가 고르게 한다. 막히면 dispatch.md의 BLOCKED 규칙.

## 절차
1. 사용자, 과업, 기기, 이 화면이 충족하는 요구사항 ID를 확인한다.
2. 흐름을 먼저 Mermaid로 그린다: 노드(화면)와 간선(행동), 실패 경로 포함.
3. 화면마다 레이아웃 영역, 컴포넌트, 상태, 문구를 정한다. 프로젝트의 디자인 토큰·컴포넌트를 재사용하고, 새 컴포넌트는 몰래 추가하지 말고 요청으로 목록에 올린다.
4. 체크리스트: 화면당 주된 행동 하나. 파괴적 행동은 확인을 받는다. 오류는 무슨 일이 일어났고 어떻게 해야 하는지 말한다. 터치 영역 44 px 이상. 글자 대비 4.5:1 이상. 모든 흐름이 키보드로 동작한다.
5. 구현으로 넘길 때는 컴포넌트 목록, 상태 표, 문구 표를 함께 준다.
