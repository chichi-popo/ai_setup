# ppt-structuring

## 루프 계약
- 성공 기준: 슬라이드마다 메시지가 하나(제목이 결론을 말함), 불릿 최대 3개, 대본 블록이 있다. 슬라이드의 모든 숫자가 원본 보고서와 일치한다. 슬라이드 수와 시간이 발표 시간에 맞는다(내용 슬라이드당 약 1.5~2분).
- 검증자: `evidence-verifier`가 슬라이드의 숫자와 주장을 원본과 대조한다. 파일을 만들기 전에 사용자가 스토리라인을 검토한다(사람 관문).
- 중단 조건: 스토리라인 수정 2회 후에는 두 가지 구조 중 하나를 사용자가 고르게 한다. 파일 제작은 렌더링 후 수정 2회까지, 그 뒤에는 남은 레이아웃 문제를 보고한다. 막히면 dispatch.md의 BLOCKED 규칙.

## 절차
1. 청중, 발표 시간, 원하는 결정이나 메시지, 원본 문서를 확인한다.
2. 스토리라인을 슬라이드 제목 목록으로 쓰되 제목은 결론으로 쓴다. 승인을 받고 dispatch.md의 승인 기록 규칙대로 해시를 남긴다.
3. 슬라이드마다 두 블록을 따로 만든다.
   - 슬라이드 텍스트: 명사구 불릿 최대 3개(완결 문장 없이 간결하게).
   - 발표 대본: 구어체 문장 2~4줄, 다음 슬라이드로 넘어가는 말 포함.
4. 비교가 있는 곳은 글 대신 차트나 도식을 쓴다. 데이터가 있는 슬라이드마다 출처 줄을 둔다.
5. 스토리라인과 숫자가 승인된 뒤에만 pptx skill로 파일을 만든다(스토리라인이 바뀌었으면 재승인). 대본은 발표자 노트에 넣는다. 모양(마스터·색·글꼴·여백)은 `doc-design` skill과 `.ai/design/DESIGN.md`를 따른다(있으면).
6. 슬라이드마다 이미지로 렌더링해 넘침과 가독성을 확인한다.

## 템플릿
```
### 슬라이드 <n>: <결론 제목>
슬라이드 텍스트:
- ...
- ...
- ...
대본: "..." (전환: ...)
출처: <파일 / 절>
```
