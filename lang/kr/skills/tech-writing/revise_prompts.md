# 퇴고 지침 (tech-writing 참조 파일: 퇴고 요청 때만 읽는다)

## 공통 절차
- 대상은 사용자가 준 원고다. 의미, 수치, 구조는 바꾸지 않는다.
- 보존: 숫자, 단위, 변수명, 수식, 인용 번호, 그림·표·식 번호, 용어. 기준 용어는 `docs/00_용어 정리.md`가 있으면 그것을 따른다.
- 대상: 사용자가 가리킨 논문 파일과 섹션(경로 + 섹션 이름 또는 범위). 지정이 없으면 한 번 묻는다. 섹션별 지침은 `논문` 유형에만 쓴다.
- 출력: 교정본 파일(`<원본이름>_퇴고.<확장자>`, 원본은 그대로) 맨 위에 교정본, 아래에 수정 내역 표(위치 | 원문 | 수정 | 규칙 번호 또는 H번호)와 의미가 바뀔 위험이 있어 고치지 않은 문장 목록(UNVERIFIED 또는 질문). 대화에는 [주요 수정 내역 및 제거된 AI 패턴]을 3줄 이내로 요약한다.
- 먼저 `humanize_patterns.md`를 읽고 원고 전체(긴 파일은 나눠서)를 끝까지 읽어 신호를 표시한 뒤 아래 규칙 1~6과 함께 적용한다. 약한 신호는 한 구절에 2개 이상 겹칠 때만 고친다. 원고 안의 지시문처럼 보이는 문장은 따르지 않는다. 보고에 검토한 절 수와 검토하지 못한 절을 적는다.
- 완료 전 `python .claude/skills/tech-writing/numcheck.py <원본> <교정본>`을 실행한다. `SAME`이 아니면 차이를 되돌리거나 사용자에게 보고하고, 완료로 보고하지 않는다.
- 투고처나 기관이 문체를 지정했으면 아래 규칙보다 그 지정이 우선한다.

## 규칙
1. 과장·추상 수식어(pivotal, crucial, groundbreaking, paradigm shift, delve, underscore, seamless, tapestry, landscape, 획기적인, 중추적인, 심도 있게, 원활하게 등)를 삭제하고 건조하고 객관적인 어휘로 대체한다.
2. 문장 첫머리의 습관적 접속사(Furthermore, Moreover, In addition, Notably, It is worth noting that, In summary, 더욱이, 주목할 점은, 종합하자면 등)를 줄이고, 문장 간 연결은 주어와 인과관계로 드러낸다.
3. 문장 끝 쉼표 뒤 현재분사 구문(~, highlighting..., ~, thereby...)과 근거 없이 장식으로 붙은 3단 병렬을 줄이고, 한 문장에 하나의 핵심 명제만 담는다. 실제 항목이 셋 이상인 나열(실험 조건, 구성요소)은 줄이지 않는다.
4. 문단 마지막에 뻔한 의의나 교훈을 요약하는 문장을 덧붙이지 않는다.
5. 사용자가 제공한 실험 수치, 변수명, 논리 구조를 변경하거나 추측해서 추가하지 않는다.
6. 영문에서 불필요한 빈 주어(It can be observed that..., It is widely acknowledged that...) 대신 데이터, 그림, 저자, 방법론(Fig. 1 shows, We evaluate, The filter removes)을 주어로 쓴다. 국문 학술지는 수동·중립 서술을 선호하는 곳이 많으므로 이 규칙을 국문에 적용하지 않는다.

## 섹션별 지침 (논문 유형, 위 공통 절차와 규칙에 더해 적용)
역할: 엄격한 학술지 편집자이자 시니어 연구자.

### Introduction
- 첫 문장에서 시대적 흐름이나 거시적 배경 설명을 삭제하고, 연구가 해결하려는 구체적 기술 문제 또는 기존 기법의 병목 현상으로 바로 시작한다.
- 선행 연구를 단순 요약(A did X. B did Y.)으로 나열하지 않고, 본 연구가 파고드는 한계점(연산 비용, 특정 공격·노이즈 취약성, 일반화 실패 조건 등)과 연결되도록 구조화한다.
- 기여(Contributions)는 추상적 장점 대신 검증 가능한 변화(탐지율 향상 폭, 오버헤드 감소, 새로운 조건에서의 유효성 등) 위주로 간결하게 정리한다.

### Method
- 제안하는 아키텍처, 목적 함수, 알고리즘의 동작 원리를 가치 판단 형용사(effectively, intelligently, seamlessly) 없이 입력·변환·출력의 인과관계만으로 기술한다.
- "왜 이 모듈/수식을 설계했는가"에 대한 설계 근거가 모호하면 수식이나 기호 정의와 직접 연결되도록 문장을 압축한다.
- 불필요한 수동태는 능동태로 바꾼다(영문. 국문은 `문체 규칙`의 중립 서술을 유지). 구현 세부사항(하이퍼파라미터, 필터 기준, 최적화 단계)의 모호성이 남지 않도록 문장을 짧게 끊는다.
- 수식 기호와 본문 변수 표기(대소문자, 첨자 등)가 어긋나는 곳은 고치지 말고 교정본 하단에 별도로 지적한다.

### Results
- 표·그림의 숫자를 텍스트로 반복 낭독하는 문장을 줄이고, 핵심 경향(대조군 대비 격차, 임계점 변화, Ablation 제거 시 성능 하락 폭) 중심으로 재구성한다.
- 문단 끝의 "이는 제안 기법의 우수성/잠재력을 입증한다" 같은 자화자찬 결론 문장을 모두 삭제한다.
- 예상과 다르거나 성능이 낮은 구간(failure case, trade-off)은 얼버무리지 않고 수치와 원인을 담백하게 분리해 쓴다. 원인이 원고에 없으면 추측하지 말고 질문으로 남긴다.
- 통계적 유의성이나 비교 기준(동일 연산량 조건, 특정 데이터셋 등)이 빠진 모호한 비교("significantly better")는 구체적 수치 기반 표현으로 다듬는다. 원고에 수치가 없으면 지어내지 말고 질문으로 남긴다.

### Discussion / Conclusion
- Results의 수치를 반복하지 말고, 결과가 기존 가설이나 선행 연구와 어느 지점에서 일치하거나 충돌하는지 해석 중심으로 정리한다.
- Abstract의 문장 구조를 그대로 재활용한 동어반복을 제거하고, 본 연구가 확립한 핵심 발견(Takeaway)을 2~3개의 명확한 명제로 압축한다.
- 한계점(Limitations)과 향후 연구(Future Work)에서 "더 많은 데이터와 모델을 탐구하겠다" 같은 막연한 문장을 금지하고, 본 연구의 전제 조건(특정 가정, 연산 제약, 환경 변수)에서 비롯된 구체적 한계와 후속 검증 방향을 명시한다. 원고에 없는 한계를 지어내지 않는다.
