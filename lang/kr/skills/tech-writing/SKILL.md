# tech-writing

## 루프 계약
- 성공 기준: (1) 모든 숫자, 인용, 참고문헌이 출처 파일(경로 + 위치)과 일치한다. (2) 구조가 승인된 개요를 따른다. (3) 근거 없는 형용사가 없다. 특허는 모든 청구항 구성요소를 상세한 설명이 뒷받침한다.
- 검증자: 새 컨텍스트의 `evidence-verifier`가 초안과 출처 목록만 받아 표를 돌려준다: 주장 | 출처 | MATCH / MISMATCH / NO SOURCE. 서식(제목, 번호, 참고문헌 형식)은 스크립트나 docx/pdf skill 출력으로 확인한다.
- 중단 조건: 수정 후 검증을 2회 반복한 뒤에도 MISMATCH나 NO SOURCE가 남으면 멈추고 사용자에게 보고한다. 빈틈을 문장 다듬기로 덮지 않는다. 막히면 dispatch.md의 BLOCKED 규칙.

## 절차
1. 유형(보고서 / 논문 / 특허), 독자, 목적 한 줄, 분량, 언어를 확인한다. 초안 전에 개요 승인을 받고 dispatch.md의 승인 기록 규칙대로 해시를 남긴다.
2. 프로젝트 자산(CLAUDE.md의 문서 절, `.ai/repo_audit_map.md` 5절, 결과 파일)으로 근거 목록을 만든다. 사실마다 ID `E1, E2...`를 붙인다.
3. 절 단위로 초안을 쓴다. 쓰는 동안은 본문에 근거 ID를 달고 마지막에 최종 인용 형식으로 바꾼다.
4. `evidence-verifier`로 검증한다. MISMATCH는 초안을 출처에 맞춰 고치며 그 반대는 하지 않는다.
5. 작성하는 동안에는 압축·간결 출력 skill을 꺼 둔다(보고서 품질을 해친다).
6. 기존 원고의 퇴고(문장 다듬기) 요청이면 `revise_prompts.md`와 `humanize_patterns.md`를 읽고 공통 절차와 유형별 적용표를 따른다. 끝나면 `numcheck.py`가 `SAME`일 때만 완료로 보고한다.

## 문체 규칙
- 상투적 표현('많은 분들이 ~', '결론적으로', '요약하자면')과 뻔한 교훈형 마무리를 쓰지 않는다. '게다가', '또한', '따라서'를 습관적으로 쓰지 않고 연결은 주어와 인과로 드러낸다. 특허 청구항·명세서의 정형 문구는 예외.
- '핵심적인', '혁신적인', '획기적인', '심도 있게' 같은 과장·추상 수식어 대신 구체적 사실과 조건으로 쓴다.
- 짧은 문장과 긴 문장을 섞는다. 가르치거나 과하게 친절한 어조 대신 실무자가 담백하게 설명하는 어조를 쓴다.
- 문장마다 앞에 없던 정보를 담는다. 앞 문장을 되풀이하는 한 줄 마무리, 본론 전 예고('~를 살펴본다'), 상대 없는 반론('~라고 생각하기 쉬우나'), 아무도 주장하지 않은 것을 부정한 뒤 잇는 역접('A가 아니라 B')을 쓰지 않는다. 부정은 독자의 실제 오해를 바로잡을 때만 쓴다.
- '정확한', '다양한', '의미있는' 같은 정도 수식은 기준값·범위·조건으로 바꾸거나 쓰지 않는다. 출처 없는 권위('연구에 따르면', '업계에서는')와 근거 없는 추정·전망도 쓰지 않는다. 개조식(~함)은 문체이므로 유지한다.
- 사용자가 제공한 사실·수치·경험 밖의 추측이나 일반론을 덧붙이지 않는다. 실험 수치, 변수명, 논리 구조를 바꾸거나 지어내지 않는다.
- 객관적인 문체. 자연스러운 곳에서는 수동태나 중립적인 서술을 쓰고 "매우 뛰어난", "놀라운" 같은 감정적 강조어는 쓰지 않는다.
- 수치로 쓴다: "지연이 120 ms에서 45 ms로 감소(62.5% 단축, 30회 측정)". 조건, 기준값, 표본 크기를 밝힌다.
- 한계는 별도 문단으로 쓴다.
- 논문: 초록(문제, 방법, 수치가 있는 결과, 시사점) -> 관련 연구 -> 방법 -> 실험 -> 논의 -> 한계.
- 특허: 배경 -> 요약 -> 도면 설명 -> 상세한 설명 -> 청구항. 독립항을 먼저 쓰고 종속항으로 좁힌다. 용어는 한 번 정의하고 똑같이 쓴다. 청구항에서 "항상", "절대", "최고"는 피한다.
- 특허와 법률 표현은 전문가가 검토할 초안이며 법적 결론을 단정하지 않는다.
- 하지 말 것: 원문을 열지 않은 출처 인용, 결론을 먼저 정하고 근거 끼워 맞추기, 요청하지 않은 절의 내용·구성 변경.

## 출력
초안 파일 + `evidence_table.md`(ID | 사실 | 출처 경로 | 위치) + 남은 빈틈 목록. Word 파일로 낼 때 모양은 `doc-design` skill과 `.ai/design/DESIGN.md`를 따른다(있으면).
