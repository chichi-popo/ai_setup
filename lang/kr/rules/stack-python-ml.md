## Python 점검 (심각도 순)
- 보안(최우선): SQL을 f-string으로 만들지 않는다(매개변수화). 셸 명령은 리스트 인자 `subprocess`. 사용자 경로는 `..`을 막는다. `eval`/`exec`, 신뢰할 수 없는 `pickle`·`joblib`·`yaml.load`, 하드코딩 비밀, 보안용 MD5/SHA1 금지.
- 오류 처리: bare `except`와 삼키는 예외 금지(구체적 예외를 잡고 기록). 파일·자원은 `with`.
- 타입: 공개 함수에 타입 힌트, 불필요한 `Any`와 누락된 `Optional` 금지.
- 관용구: 가변 기본 인자(`def f(x=[])`) 금지, `is None`, `isinstance`, 매직 넘버는 이름 있는 상수나 `Enum`, 반복문 안 문자열 `+` 대신 `"".join`.
- 구조: 함수 50줄 초과, 인자 5개 초과(dataclass), 중첩 4단계 초과, 중복 코드는 분리한다.
- 동시성: 공유 상태에는 락, 동기·비동기 혼용 주의, 반복문 안 쿼리(N+1)는 일괄 조회.
- 사소한 것: import 순서, `print` 대신 `logging`, `import *` 금지, 내장 이름(`list`, `dict`) 가리기 금지.

## ML 점검 (데이터·학습·평가·서빙을 건드릴 때만)
- 누수: 분할은 시간·엔터티(사용자) 단위로 한다. 시간 의존 데이터에 무작위 분할 금지. 스케일러·인코더·토크나이저는 학습 분할에서만 `fit`. 예측 시점에 없는 컬럼(사후 값, 미래 라벨)을 특징으로 쓰지 않는다.
- 재현성: 코드, 설정, 데이터 버전, 시드로 노트북 상태 없이 재실행되어야 한다. 하이퍼파라미터·전처리·의존성 버전·코드 해시·지표·산출물 위치를 기록한다. 난수와 GPU 비결정성은 의도적으로 다루고, 재시도가 이전 산출물을 덮어쓰지 않게 버전을 붙인다.
- 평가: 기준선(현재 모델 또는 단순 모델)과 비교한다. 지표는 오류 비용에 맞춘다(정확도 하나로 판단하지 않는다). 중요한 부분집합(slice)별 지표와 오류 사례를 직접 본다. 테스트 세트에 반복 튜닝하지 않는다. 승격 기준은 선택 전에 정하고 기준 미달이면 막는다.
- 서빙: 학습과 서빙 전처리를 공유하거나 동등성을 테스트한다. 입력 스키마는 누락·범위 밖 값을 거부한다. 출력과 로그에 모델 버전을 넣고, 시간 제한과 폴백, 이전 산출물로의 되돌리기 경로를 둔다.
- 개인정보·비밀: 데이터셋, 노트북, 로그, 산출물에 개인정보·키가 없어야 한다. 노트북이 운영 재학습에 필수면 지적한다.
